# 架构说明

`AgentEngine` 是执行中枢：请求模型，等待整轮成功，校验工具参数，执行工具，持久化结果，再发送下一轮。CLI 只负责配置和渲染事件，不直接编排模型 SDK。

`ArkProvider` 用 `AsyncArk` 的 Responses API。流式文本立即显示；工具增量只聚合，整轮 `response.completed` 才交给内核执行。供应商原始输出完整保存并在后续请求回传，工具结果用同一个 `call_id` 对应。

文件工具校验仓库内真实路径、文件指纹和唯一旧片段。修改前后的快照用于 Agent 差异与显式恢复，不执行 Git 重置。命令工具使用 argv，授权绑定完整命令和工作目录，stdout/stderr 并发排空；中断清理进程组并记录结果。

`JsonlSessionStore` 用单写入文件锁与追加日志记录执行证据。恢复时用已完成工具结果重建历史，未完成调用用“状态未知、未重放”的结果闭合协议。文件快照不承诺撤销命令和外部副作用。

`ContextManager` 控制上下文预算，按完整响应与工具结果分组，整理旧轮次时保留最近两轮；摘要失败就停止当前任务并保留日志。

核心模块和测试都使用中文说明设计原因，可结合 `examples/offline_demo.py` 的真实文件改动与命令结果学习。离线演示使用固定模型替身，仅说明执行机制；真实模型任务需要 Ark 配置。
